A stack is the best choice for undo and redo since it uses last-in and first-out. The most recent action should be the first action when reversed. When I perform an action, it gets pushed to the undo stack. Then when I undo that action, it is pushed onto the redo stack. Then redoing moves  it back to the undo stack. Then when the new action is performed, the redo stack is cleared since there is no redo history to match the requirements. 
A queue is better suited for help desks since it follows the first-in and first-out principles. A customer will need information in the order they arrive. The queue helps add each customer at the back and remove the next customer till the front.
My implementations use linked nodes instead of the normal Python built-in lists. The individual node stores a value and a reference to the next node. Then the stack tracks, while the queue tracks its front and rear. Python lists use dynamic arrays that have direct access by index. Lists are effective as stacks using append and pop. However, removing the first list element needs prior elements to shift. My queue helps avoid shifting by updating pointers. Custom structures require extra memory for reference but show how stack and queue operations may work on a basic level.
